# 微信图片识别流程

目标：用户在微信发送训练截图、手表截图、码表截图或身体状态图片时，教练必须先识别图片内容，再决定记录、分析或追问。连续多张图片要当作同一组输入处理，不要逐张回复。

## 处理顺序

1. 如果 OpenClaw 已经在消息里提供 `[Image] Description`，直接使用这段图片说明，不要再让用户重复描述。
2. 如果消息里只有 `media://inbound/...`，调用本地开源 OCR 识别入口：

```bash
python3 scripts/image_intake.py "media://inbound/图片文件名.jpg"
```

3. 识别入口默认只使用 Tesseract OCR 和项目内的中文识别数据，不把用户图片发给第三方接口。
4. 如果识别成功，把识别出的训练字段交给 `training-memory` 保存，并按需要调用 `workout-feedback`。
5. 如果识别失败，只问用户补充最关键的一句话：

```text
我收到图片了，但这次没能自动读出里面的训练数据。请补一句：项目、距离、用时、平均心率和身体感受。
```

不要说“看不到图片”后直接结束，也不要假装已经看懂图片。

## 多张图片

用户可能一次训练连续发送多张截图，例如概览图、配速图、心率图、分段图。

处理规则：

- 同一用户短时间内连续发送的图片，先合并成图片组。
- 不要对每张图片分别回复。
- 每张图分别识别，最后合并成一次训练记录。
- 如果图片后面还有文字说明，把文字作为同一次训练的主观感受或补充字段。
- 只有在图片组识别完成并判断用户表达结束后，才统一回复一次。

## 可识别内容

- 跑步、骑行、游泳、铁三赛段、越野跑截图。
- 距离、用时、配速/速度、心率、功率、步频/踏频、爬升、消耗。
- 训练类型、完成情况、疲劳、疼痛、恢复感受。
- 手表或运动 App 截图中的趋势、分段、心率区间等信息。

## 数据隔离

图片识别只服务当前发送图片的微信用户。识别结果保存前必须按当前 `channel + account_id + peer_id/sender_id` 定位用户，不得写到其他人的档案。

## 失败边界

当前第一版图片识别使用开源 Tesseract OCR，适合读取运动 App、手表、码表截图里的文字和数字。它不是完整视觉理解模型；如果图片是纯图形、截图模糊、文字过小或识别失败，教练需要明确说明没能读出图片，并请求用户补关键字段。最多追问 1 个问题。

默认不启用外部视觉服务。除非所有者明确同意，不要把用户图片上传给第三方模型。

## 开源依赖

- Tesseract OCR：本地 OCR 引擎，项目地址 <https://github.com/tesseract-ocr/tesseract>。
- `user-data/tessdata/chi_sim.traineddata`：中文简体识别数据，来自开源 tessdata_fast 训练数据 <https://github.com/tesseract-ocr/tessdata_fast>。
- Python `Pillow` / `pytesseract`：图片预处理和 OCR 调用。

后续如果需要更强的“看图理解”，可以在同一个入口后面接本地视觉模型，例如 Ollama 里的视觉模型。当前第一版先保证训练截图里的文字和数字能被读取。
