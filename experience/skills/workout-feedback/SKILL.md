# 训练反馈

## 何时使用

当用户记录一次训练，或描述训练感受、配速/均速/功率、心率、疲劳、疼痛时使用。用户发送训练截图、手表截图、码表截图时，也应在图片识别完成后使用。

注意：`workout-feedback` 不是孤立评价单次训练。尽量结合近期身体状态及已确认计划；没有这些数据时说明缺口。计划执行通过产品的预览与确认工具保存，身体状态通过 Check-in 或训练记忆流程另行确认。

所有项目先参考 `../../docs/endurance-training-methodology.md` 的统一反馈闭环：同时解释外部输出、内部成本、机械/技术负荷和非训练压力，不用单一设备分数裁决。

跑步训练反馈应参考 `../../docs/running-coach-principles.md`。这些原则只作为教练判断层，不替代用户自己的近期数据和安全规则；重点关注跑步经济性、配速纪律、恢复窗口和长距离补给。

## 需要收集的输入

必须尽量识别：

- 日期（缺省默认今天）。
- 运动项目（跑步/骑行/游泳/铁三赛段）。
- 距离或时长。
- 配速（跑步）/ 均速或功率（骑行）/ 每 100 米配速（游泳）。
- 主观感受。
- 疲劳程度（文字或 1-10）。
- 是否疼痛。
- 是否按计划完成（如有计划）。

如果输入来自图片识别结果，优先使用识别出的字段；识别不确定的字段不要强行补全。

可选识别（有则参考，无则跳过，不追问）：

- 平均心率、最高心率。
- 天气、路线海拔/爬升。
- 睡眠和压力。
- 鞋子、车、泳池/公开水域等装备或环境变化。

## 反馈前的必要上下文

1. 用 `get_activity_detail` 和 `analyze_session` 读取本次活动的项目、时长、距离、圈段、质量标记和相似训练参考；相似训练只作描述，不代表体能变化。没有活动记录时只根据用户提供的内容给有限反馈，不假装数据已入库。
2. 用 `get_today_report` 和 `get_recent_check_ins` 了解近期疲劳、睡眠、疾病、疼痛与缺口；缺失表示未知。疼痛和疾病信号优先交给 `injury-risk`。
3. 用户询问计划执行时，用 `list_training_plans` 找到已确认计划，再用 `list_plan_execution` 列出计划课与同日或相邻日活动候选。候选即使唯一，也不能自动认定为已完成。
4. 用户确认具体计划课和活动后，可用 `compare_plan_actual` 展示项目、日期与时长差异。只有在用户明确给出完成状态、RPE、疼痛和原因后，才用 `preview_plan_execution` 展示待保存内容；用户看到预览并明确同意后才用 `confirm_plan_execution` 写入。

## 行为规则

- 先给简短、可核验的训练反馈。对数据标明观测、产品计算、用户自述和推测；缺少数据时标明限制。
- 跑、骑、泳分别使用 min/km、km/h、min/100m。铁三不把总距离除以总时长得出跑步配速。
- 分析运动时长、距离、圈段、心率或功率时只使用实际存在的字段。全程平均值不能冒充逐段强度分布；活动样本数存在不等于逐点样本已被分析。
- 相似训练参考只比较近 180 天、同来源项目、距离和时长相近且无质量标记的历史活动；运动强度、地形和天气并未全部控制，不能由差异直接宣称进步或退步。
- 计划完成状态、主观用力、疲劳与疼痛都需要用户核对；只凭设备数据不写入个人状态或计划执行。没有明确确认时只展示预览，不说“已记录”。
- 用户超量、少练或跳课时先问原因与恢复；漏训不补债，不因一次表现好就自动加量。疼痛、疾病或功能受限时停止建议进阶，并按产品安全结果处理。
- 身体状态需要长期保存时，按用户意图组合 `athlete-recovery` 或 `training-memory` 的预览与确认流程；本 Skill 不自行写入身体状态或 AI 反馈。

## 中长跑反馈规则

- 跑步训练不只看配速，还要看心率、体感、后半程是否掉速、是否出现步频/步幅或动作异常。
- 评价跑姿时聚焦“是否省力”：放松、协调、减少制动和无谓动作，不把前掌或后跟着地当作唯一标准。
- 不用 180 步/分钟作为统一目标。步频和步幅只与用户自己的相近配速、坡度和疲劳条件比较；需要调整时只给小幅、短段尝试。
- 用户刚换鞋、改着地方式、明显缩短/拉长步幅时，把小腿、跟腱、足底和膝部列为负荷转移观察点，不承诺某种技术一定防伤。
- 长跑、半马、全马专项、铁三跑步段和超过 60 分钟的耐力训练，如果前快后慢、心率漂移明显或后半程体感崩，优先提醒配速纪律。
- 用户超量完成、完成长距离、下坡多、比赛或连续关键课后，不盲目表扬；先判断恢复窗口是否足够。
- 超过约 60 分钟的训练、热天训练或长距离专项课，简短提醒补水补碳是否已经在训练中演练。
- 高温高湿下同配速心率或 RPE 升高时，先按环境修正评价，建议按体感/谈话测试降速并补水，不直接判断能力退步。
- 寒冷天气或强度课前提醒渐进式动态热身；训练中断、疾病或伤病后复跑，先恢复轻松有氧和规律，再恢复总量与强度。
- 只有用户提到跑姿、步频、步幅、疼痛、视频或截图时，才展开技术动作分析；普通反馈只给一条最关键动作提示。

## 输出格式

```text
训练反馈：
- 项目与日期：
- 客观表现：时长、距离、圈段及可用指标
- 相似训练参考：样本数与中位数；或历史不足
- 与计划的关系：候选 / 用户已确认 / 无可比计划
- 当前身体状态：用户已报告的事实与未知项
- 质量与风险：依据、质量缺口和不确定性
- 下一次训练建议：保守选项及触发复核的条件
- 保存状态：未保存 / 预览待确认 / 用户已确认写入
```

## 风险信号

出现以下情况时提高风险等级：

- 局部疼痛（任何运动项目）。
- 疼痛随训练加重。
- 连续多天疲劳。
- 同类型训练配速/均速明显下降但主观强度升高。
- 心率异常升高（与平时同强度训练相比）。
- 睡眠差且仍安排强度训练。
- 周训练量、关键课密度或跑步冲击相对个人近 3–4 周基线突然增加；百分比只作观察信号，不作统一安全线。

## 身体状态记录边界

用户主动描述疲劳、睡眠、压力或疼痛时，可询问是否记录，并交给相应的 Check-in 或训练记忆预览/确认工具。不能把模型对“恢复不足”的推断直接写成用户事实。用户明确说无痛也只作为该次用户自述，不推断过去两周都无痛。
