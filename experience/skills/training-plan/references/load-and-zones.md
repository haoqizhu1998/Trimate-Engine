# 负荷、能力与强度区间

## 当前产品口径

按跑步、骑行、游泳分别读取近 7 天和 28 天的训练频率、分钟数、距离与同来源、同算法的设备负荷。`get_training_load_context` 的比值只描述近期变化；不能独自预测伤病、证明恢复充分或许可加量。不同项目的分钟数可列在同一日历中，设备负荷、TSS、session-RPE 不互相换算。计划内 `expected_load` 是分钟数代理，不是生理负荷。

训练取舍同时看外部输出、用户报告的 RPE、疲劳、睡眠、疼痛、疾病和非训练压力。缺少主观状态表示未知。近期训练史不足或来源冲突时，写明数据缺口与保守假设，不生成精确风险分数。

## 项目专项参考

调用 `get_sport_calibration` 核对用户确认的跑步阈值配速、骑行 FTP 或游泳 CSS 的测试日期、来源、版本和有效期。当前有效值只能提供宽区间参考；过期、估计或缺失时用 RPE 与谈话测试，不复制旧配速、功率或心率区间。测试本身算关键课，疼痛、疾病、明显疲劳或赛前减量时不安排强测。

- 跑步轻松课：能完整说话，RPE 约 2–3；较快专项课需结合有效测试与当前身体状态。
- 骑行：有可靠功率和有效 FTP 时可解释宽功率范围；缺少功率计时不虚构瓦数。
- 游泳：有效 CSS 可作持续与阈值训练的宽参考；高强度仍需结合重复距离、休息和动作质量。
- 铁三：游、骑、跑分别显示训练量与关键课密度，尤其单独观察跑步冲击与骑后跑反应；不生成跨项目统一 TSS。

## 调整依据

复盘时优先看同项目、同类型且数据质量相容的课程。`list_plan_execution` 只给可能对应的活动，用户确认后才可把完成状态、RPE 和疼痛纳入下周计划。少于三次可比关键课时只说明历史不足，不据此升级难度；恢复和症状门始终优先。允许进阶也只预览一个主要变量的变化，不能同时提高总量、强度和关键课密度。

强度分布以低强度有氧为基础，但不把固定 80/20、每周 10% 增量或 ACWR 阈值写成通用处方。更详细的研究来源及适用范围见 `../../docs/endurance-training-evidence-base.md`。
