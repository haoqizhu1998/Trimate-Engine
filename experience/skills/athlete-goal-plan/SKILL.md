# 目标与训练计划

先读 `get_sync_status`、`get_data_quality`、`get_today_report`、`get_training_load_context`、`list_goals` 和需要继续的 `list_open_planning_drafts`。从用户的原话调用 `propose_goal`；只追问阻碍当前目标草案的必要信息。展示草案的类型、指标、期限、优先级（1 最高，5 最低）、假设、冲突和数据缺口。仅当用户明确批准所展示的最新版本，才调用 `confirm_goal`。

用户可以随时新增、替换或删除目标。新增走 `propose_goal` → `confirm_goal`；替换或删除走 `preview_goal_change` → `confirm_goal_change`，展示原目标、新目标、原因和受影响计划后才请求明确确认。目标变化后先调用 `review_plan`，对受影响的已批准计划调用 `preview_plan_update` 生成新版草案；若旧约束不适合新目标，则重新收集约束并调用 `preview_plan`。不要继续把旧目标计划说成当前有效建议。

计划必须以已确认目标为依据。先用 `get_training_preferences` 读取用户已确认的私有排课偏好；Skill 中的示例只是方法，不是用户个人事实。收集开始日期、每周可用时间、不可训练日、运动类型与周上限。单周调用 `preview_plan`；希望按专项板块安排多周时调用 `preview_plan_blocks`，指定 2–12 周，并优先让用户给出重点项目顺序 `focus_sequence`；若未指定顺序，仅在私有档案已确认 `focus_blocks` 偏好时按所选项目轮换。单项目传 `sport`；铁三等多项目传按优先顺序排列的 `sports`。用户可选本周重点项目、关键强度课和长课的偏好星期、是否跨项目穿插低强度有氧；已确认的档案偏好在本次未指定时生效，本次明确指定的参数优先。可传 `use_saved_preferences=false` 仅按本次输入排课。没有明确偏好时不要假定每周三、周日或固定四周轮转。核对七天内每个项目是否实际排到课，展示逐日安排、各项目分钟数、关键课数、总量、限制、证据缺口与风险。没有可靠个人速度基线时不编造距离、配速、功率或 TSS。

`preview_plan_blocks` 返回的未来周仅有日期与重点项目，属于可修订预测；只有首个七天是可确认的逐日训练草案。每到下一周，先 `review_plan`，再用 `preview_plan_update` 依据最新目标、训练数据、主观状态和安全结果生成那一周的草案，展示差异后才可确认。偏好版本变化或板块周期结束时重新预览整个周期。当前没有自动渐进量、双练或赛事减量处方；不可用日或证据不足可能使某项目或关键课无法安排。用户明确批准最新预览后才调用 `confirm_plan`；修改后必须重新预览。

用户训练中临时改动时，先区分“已经发生的训练”与“希望修改接下来的一课”。已发生的训练优先读取同步后的活动；没有设备记录时，仅在用户明确要求保存后使用 `preview_training_memory` / `confirm_training_memory` 记录其自述。调用 `review_plan` 查看新活动与原课表的可能差异；同日活动只是待用户核对的候选匹配，不能自动认定为已完成某节课，也不能把缺失活动当成跳过。对当前七天计划中尚未发生的一课，调用 `preview_plan_adjustment`：可跳过、缩短、改为低强度其他项目或移至本周可用日；展示原安排、新安排、周时长差异、原因和安全结果。该工具不自动补课、不加量、不改动其他课；若用户要改变多节课、可用时间或整周目标，重新预览计划。新训练数据或安全状态变化会使旧草案失效；只在用户看过最新完整草案并明确同意后调用 `confirm_plan`。

若安全信号或数据缺口使建议不可靠，先说明并降低建议强度；不能通过 Skill 绕过应用用例的校验。确认完成后可用 `list_training_plans` 核实保存版本。未确认时明确称为草案。
