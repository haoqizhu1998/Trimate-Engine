# 训练负荷

本 Skill 的解释边界遵守 `../../docs/endurance-training-methodology.md`。训练负荷是计划和复盘的上下文，不是伤病预测器；任何“风险等级”都必须再结合疼痛、睡眠、疲劳、恢复、疾病、生活压力和项目专项机械负荷。

## 何时使用

当用户问“最近练得重不重”“训练负荷多少”“疲劳风险”“ACWR”“这周负荷高不高”，或系统同步 Garmin 新训练、保存手动训练、生成训练反馈、周报和训练计划调整时使用。

`training-load` 是独立计算能力，不负责制定训练计划，也不单独替代身体状态判断。它应和 `workout-feedback`、`weekly-review`、`periodic-training-summary`、`training-plan` 配合使用。

## 输入来源

优先使用当前用户自己的数据，禁止跨用户读取：

- `workout_logs`：训练日期、项目、距离、时长、心率、功率、主观疲劳。
- `external_imports.raw_json`：Garmin 活动原始数据，例如训练负荷、训练效果、TSS 类字段。
- `body_status_logs`：疲劳、睡眠、压力、疼痛、恢复信号，仅作为风险解释，不直接伪造成负荷分数。

## 计算口径

负荷结果默认写入 `training_loads`：

- `load_score`：单次训练负荷分数。
- `method`：计算方法，例如 `garmin_training_load`、`garmin_tss`、`session_rpe_v2`、`fatigue_proxy_v2`、`duration_minutes_v2`；旧数据可保留 legacy 方法名。
- `confidence`：`high` / `medium` / `low`。
- `acute_load_7d`：截至该训练日的 7 日急性负荷总和。
- `chronic_load_28d`：截至该训练日的 28 日负荷折算周均。
- `acwr`：7 日急性负荷 / 28 日周均慢性负荷。
- `risk_level`：数据库兼容字段，表示负荷趋势提醒（低 / 中 / 高），不是伤病概率。

优先级：

1. Garmin 原始训练负荷：高置信度，只与相同 Garmin Load 口径累计。
2. 设备原始 TSS 类字段：高置信度，只与相同 TSS 口径累计。
3. 时长 × 明确记录的 session-RPE：中置信度的内部负荷。
4. 时长 × 训练后疲劳评分：仅作低置信度代理，并明确疲劳不等于 session-RPE。
5. 仅时长：保留为低置信度时长代理，不自造 RPE 或 TSS。

Garmin Load、TSS、session-RPE、疲劳代理和时长代理是不同量纲，禁止放入同一急性/慢性负荷序列。Garmin 训练效果只作定性上下文，不通过自造公式换算为 RPE。只有平均心率而没有个人最大心率、静息心率或阈值心率锚点时，不使用固定绝对心率档位加权。

## 回复规则

- 可以告诉用户“训练负荷分数”和“趋势风险”，但不要把估算值说成精确生理指标。
- 使用估算时必须说明“估算”或“置信度”。
- 解释 ACWR 时，用普通中文说明“近期负荷相对过去基线抬升或下降的程度”。`1.3`、`1.5` 等值只能触发进一步复核，不能直接宣布安全、危险或受伤概率；建档不足 28 天、近期停训或负荷估算置信度低时尤其谨慎。
- 不要只看负荷分数下结论；必须结合睡眠、疼痛、疲劳、训练准备度和用户目标。
- 如果缺少足够数据，明确说明“这次只能按时长或 session-RPE 粗估”，不要编造功率、FTP、阈值心率或 TSS。

## 安全边界

- 训练负荷不是医学诊断。
- 如果负荷升高同时出现疼痛、睡眠差、训练准备度低或异常高心率，应保守建议降负荷或恢复。
- 疼痛加重、改变动作、胸部不适、晕厥或异常呼吸时，优先安全建议，必要时建议寻求专业人士帮助。
