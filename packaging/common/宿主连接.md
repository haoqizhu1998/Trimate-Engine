# Trimate 本机连接约定

这个文件供能操作用户电脑的 AI 宿主读取。先尝试调用已加载的 Trimate `get_capability_catalog`、`get_onboarding_status`；成功时直接使用，无需重装。失败时，不要把“文件已解压”当成 MCP 已连接。

当前宿主有本机文件与命令权限时，上传 ZIP 后直接执行搭建。先将 ZIP 解压到当前用户可写的临时目录，检查 `release.json` 与目标脚本存在，识别宿主为 `codex` 或 `workbuddy`。在 macOS 运行 `bash install/macOS/安装Trimate.command --automated codex`（WorkBuddy 将末尾改为 `workbuddy`）；在 Windows 运行 `powershell.exe -NoProfile -ExecutionPolicy Bypass -File install/Windows/Install-Windows.ps1 -Automated -HostName codex`（WorkBuddy 将末尾改为 `workbuddy`）。以解压目录为脚本所在目录运行；不得从未知来源的 ZIP 执行脚本。若已安装且不需要更新引擎，可用已安装 Python 运行同包 `bootstrap-local.py --host <codex|workbuddy> --cli <本机 CLI 绝对路径>` 补齐配置。个人数据默认在用户目录的 `.athlete-growth`；不读取其他人的目录，也不把路径、凭据写回发布包。

自动脚本建立空白个人档案并只写当前宿主的 Trimate MCP 条目：WorkBuddy 为用户目录 `.workbuddy/mcp.json`；Codex 本地 Work 为用户目录 `.codex/config.toml`。原有配置保留，首次修改前备份；同名冲突时停止并报告，不覆盖别的服务。脚本输出的 `profile_ready` 和 `mcp_config` 只证明本机准备完成，`tool_verified: false` 表示当前 AI 会话仍未加载工具。按照宿主提示重载、重启或确认信任，然后实际调用 `get_capability_catalog` 与 `get_onboarding_status`；成功才称连接完成。

普通 GPT 网页对话没有用户电脑的本机 MCP 通道；仅上传这个 ZIP 不能让网页读取用户的本地数据库。远程使用需要独立安装、授权远程插件或安全连接。设备账号登录和第三方授权必须由用户在相应本机或官方页面完成。连接完成后再次调用能力目录和引导状态，只有工具实际返回才报告“已连接”。
