# 模型宿主优先的新手引导

> 这是未来宿主适配器的目标交互设计，不是当前已安装能力。当前 GPT/Codex、WorkBuddy、Coze 传输和持久化引导状态机尚未实现；已可用的新手步骤、CLI 回退与 macOS 自动化边界见 [新手与模型宿主引导](onboarding.md)。

## 1. 目标用户与 JTBD

**Persona**：使用 ChatGPT/Codex、WorkBuddy 或 Coze 的个人运动者，有 Garmin 或运动文件，但不理解训练建模和产品内部命令。

**JTBD**：“当我想更科学地训练时，我希望在熟悉的 AI 对话中连接自己的数据，快速理解当前状态并得到下一步行动，而不是学习一套软件。”

**首次价值目标**：安装开始后 10 分钟内，用户看到一份带证据、置信度和下一步行动的个人报告。

## 2. 交互原则

1. 用户只需描述目标，不需要记工具名或 CLI 参数。
2. 一次只问一个决策，默认值明确且可修改。
3. 引导进度由产品引擎保存，不依赖模型记忆或对话上下文。
4. 每个等待状态都说明“正在做什么、还需要多久、可否安全重试”。
5. 不强迫用户在首次引导中完成所有资料；仅收集当前结论必需的字段。
6. 原始健康数据不默认发给模型；宿主优先获得本地计算后的最小化结果。

## 3. 统一启动契约

无论用户从哪个模型软件进入，宿主包都按相同顺序启动，不把安装差异带入后续业务对话：

```text
安装宿主包或添加连接
  → 发现本地/远程产品引擎
  → system.get_status 检查版本与可用能力
  → 本地一次性配对或远程 OAuth
  → 检查后台运行器与通知渠道
  → onboarding.get_state 恢复进度
  → 只呈现当前唯一推荐动作
```

首次回复固定回答四件事：产品能做什么、数据存在哪里、当前需要用户做什么、预计何时看到第一份结果。宿主不得先要求用户理解 MCP、API Key、数据库路径或 CLI 命令；这些只在自动检测失败后的高级诊断中出现。

## 4. 旅程地图

| 阶段 | 触点 | 用户行动 | 情绪 | 主要阻力 | 产品机会 |
|---|---|---|---|---|---|
| 发现 | 宿主插件/Skill 市场 | 了解能解决什么 | 🤔 | 不知道与普通 AI 问答有何不同 | 展示“基于你的真实数据”和本地优先承诺 |
| 安装 | 宿主安装页/配对页 | 安装宿主包并连接引擎 | 😐 | MCP、URL、Token 等术语过多 | 一键检测宿主能力，只给出当前平台的安装路径 |
| 建档 | AI 对话 | 确认时区、单位、主要运动 | 🙂 | 担心要填大量资料 | 只问最小必填项，余下信息渐进补齐 |
| 连接数据 | 授权页/导入器 | 选择 Garmin、文件或演示数据 | 😬 | 不理解区域和凭据安全 | 自动判断可用路径，密码只在授权面输入 |
| 开启自动化 | AI 对话/系统授权 | 允许后台运行和选择通知粒度 | 😐 | 担心耗电、打扰或后台失效 | 解释本地/托管差异，提供状态和随时暂停入口 |
| 同步 | AI 进度消息 | 等待历史数据导入 | ⏳ | 不知道是否卡住或会否重复 | 分批落盘、进度可见、可安全重试 |
| 数据体检 | 对话卡片/文本 | 确认覆盖范围和缺口 | 😌 | 看不懂技术性质量报告 | 用“可用/不完整/需要补充”三层语言呈现 |
| 首次分析 | AI 对话 | 查看现状、风险和行动 | 🤩 | 指标太多、不知道看什么 | 首屏只显示“我现在怎样/为什么/下一步” |
| 首周计划 | AI 对话+确认 | 设置目标与可训练时间 | 🙂 | 不会填负荷或周期参数 | 使用目标模板和日历式问题，预览后确认 |
| 日常使用 | 原宿主对话/通知 | 接收摘要、Check-in、查看今日建议 | 😊 | 不知道数据是否新鲜或通知为何触发 | 显示同步时间与依据，固定为“自动同步→提醒/摘要→Check-in→训练反馈” |

## 5. 关键时刻

- **Aha moment**：用户看到第一份个人报告，并能追问“为什么这样判断”。
- **Moment of truth 1**：连接健康数据前是否信任隐私和凭据边界。
- **Moment of truth 2**：同步过程是否可见、可恢复、无重复。
- **Moment of truth 3**：第一份报告是否给出了明确且不过度承诺的行动。
- **Moment of truth 4**：后台同步失效时是否明确告知数据已经过期，而不是继续生成看似最新的建议。
- **流失触发点**：手工填写连接 URL/Token、长时间没有进度、首页空白、要求理解 HRV/ACWR 等术语、丢失引导进度、重复通知或静默停止同步。

## 6. 宿主安装路径

### ChatGPT / Codex

- Codex/能力包环境：安装本地 Plugin，由 Plugin 启动或定位本地引擎。
- ChatGPT 远程对话：首选自定义 MCP/Plugin；无完整 MCP 权限时使用只读 MCP 或 GPT Action。
- 本地数据不直接暴露到公网；使用受支持的安全隧道或用户自托管端点。
- 不支持后台主动消息时，分析结果进入未读 Inbox，并由本机系统通知或下次对话展示。

### WorkBuddy

- 以 MCP 插件安装包为主；
- Skill 只负责将自然语言需求映射到统一工具；
- Workflow 用于安装检查、首次引导和日常固定闭环，不重写训练算法。

### Coze

- 通过自定义 Plugin/OpenAPI 调用同一 HTTP 工具契约；
- 新手引导用 Workflow 组装，每次都先调用 `onboarding.get_state`；
- 账号绑定使用 OAuth，不在 Bot 变量、Prompt 或知识库中存储 Garmin 凭据。

## 7. 引导状态与工具

| 状态 | 用户所见 | 主要工具 | 完成条件 |
|---|---|---|---|
| `engine_ready` | 欢迎、隐私与能力说明 | `system.get_status` | 引擎健康且已配对宿主 |
| `profile_required` | 时区、单位、主要运动 | `onboarding.answer` | 建立 `athlete_id` |
| `data_source_required` | Garmin/文件/演示三选一 | `source.list_options` | 至少选择一个数据路径 |
| `automation_setup` | 同步频率、后台状态、通知策略 | `automation.configure`、`notification.configure` | 运行器健康或用户明确选择手动模式 |
| `syncing` | 覆盖范围、进度和重试提示 | `source.get_sync_status` | 至少一个批次成功落盘 |
| `baseline_partial` | 当前数据+“尚未建立基线” | `report.get_today` | 允许继续，但降低置信度 |
| `baseline_ready` | 完整基线与异常解释 | `report.get_weekly` | 历史覆盖达到指标要求 |
| `goal_required` | 四个目标模板 | `goal.create` | 至少一个激活目标 |
| `check_in_required` | 一分钟主观问题 | `check_in.record` | 完成或明确跳过 |
| `first_plan_review` | 7 天计划预览和依据 | `plan.create_first_week` | 批准、要求修改或拒绝 |
| `active` | 今日状态和下一行动 | 日常工具组 | 进入日常闭环 |

## 8. 数据成熟度

- 0 天：仅提供建档、目标和缺口说明。
- 1–6 天：可展示当日观测，不称为个人基线。
- 7–27 天：提供初步趋势并明确降低置信度。
- 28 天及以上：启用完整个人基线。
- 有历史 Garmin 数据的用户可在首次同步后直接进入 `baseline_ready`。

## 9. 日常闭环

```text
后台自动发现并同步新数据
  → 自动运行确定性分析与安全规则
  → 有行动价值时通知；普通变化进入摘要
  → 用户打开宿主，补充 30 秒 Check-in
  → 结合 Check-in 重新评估安全规则
  → 今日状态与计划
  → 训练后记录完成情况和 RPE
  → 下次建议使用该反馈
```

## 10. 验收指标

- 首次价值时间中位数 < 10 分钟；
- 引导完成率 ≥ 70%；
- 完成引导的用户 100% 获得一份报告和一个明确行动；
- 跨宿主恢复引导时不丢失状态；
- 安装失败、授权失败、同步中断均有可执行的恢复动作；
- 后台运行器离线、数据过期和通知投递失败均在下一次交互中可见；
- 重复来源数据不会产生重复分析或重复通知；
- 宿主迁移不要求复制或重新导入个人数据。
