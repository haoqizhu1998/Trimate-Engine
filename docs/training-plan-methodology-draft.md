# 训练计划制定能力：方法论草案（待用户讨论）

> 2026-10-27，讨论稿，不是已经上线的计划处方，也不替代医疗或专业教练评估。这里先定义产品应如何决策，再决定算法和交互。不要把个人数据、Garmin 凭据或真实计划写入产品仓库。

## 1. 能力定义

输入明确目标、现实时间约束、既往运动暴露和当前身体状态，生成**可执行、可解释、可修改**的训练计划；训练发生后，用实际完成情况和主观反馈滚动调整。目标不是一次生成一张“完美课表”，而是持续做出有依据的下一步安排。

第一版建议以**健康成人的耐力运动及配套力量训练**为范围，跑步、骑行、游泳采用同一流程但不同项目规则。青少年、孕产期、重大疾病、术后和损伤康复不套用通用自动计划；相关情境需要专门规则和专业人员参与。

## 2. 证据原则

| 原则 | 依据与产品解释 |
|---|---|
| 先保证可持续，再优化训练量 | [WHO 身体活动指南](https://www.who.int/publications/i/item/9789240015128/)给出人群健康活动基线；[ACSM 2026 力量训练立场文件摘要](https://www.acsm.org/wp-content/uploads/2026/03/Resistance-Training-Position-Stand-infographic.pdf)强调一致性、与目标匹配及循序渐进。人群建议不是每位运动员的比赛处方。 |
| 结合内外负荷与主观感受 | [IOC 运动负荷与损伤共识](https://bjsm.bmj.com/content/50/17/1030.long)建议个体化、反复监测外部负荷、内部反应和主观状态；任何单个指标都不足以识别适应不良。 |
| 滚动个体化，但不承诺特定收益 | 一项 [30 人休闲跑者研究](https://pubmed.ncbi.nlm.nih.gov/35975912/)中，基于 HRV、主观恢复和跑速-心率指标调整训练的组获得更大 10 km 改善。这支持“测试个体化调整”，不构成产品效果保证，也不说明 HRV 可单独决定训练。 |
| 不把某个比例当伤病预测器 | 早期 IOC 共识提出监测快速负荷变化，但后续[方法学批评](https://pubmed.ncbi.nlm.nih.gov/32502973/)指出急慢性负荷比（ACWR）的因果和统计问题。产品可展示变化趋势，不能仅凭 ACWR 阈值宣称或自动判定损伤风险。 |
| 强度分配是选项，不是通用公式 | 不同耐力强度分配在[休闲跑者随机试验 A](https://pubmed.ncbi.nlm.nih.gov/23752040/)和[随机试验 B](https://pubmed.ncbi.nlm.nih.gov/33344993/)中均可能改善表现，比较结果受人群、训练量和方案影响。第一版不硬编码“80/20 必然最佳”。 |
| 身体目标不能压倒健康边界 | [IOC REDs 共识](https://bjsm.bmj.com/content/57/17/1073)提醒持续能量不足可损害健康与表现；产品只识别需要进一步评估的线索，不自行诊断或给出极端能量限制。 |

## 3. 决策流程

### A. 建立计划上下文

必须由用户确认：首要目标和优先级、项目、赛事日期（若有）、每周可用日与时间、不可训练日、计划周期、现有伤痛/疾病与禁忌、器材及场地。可选：年龄段、经验水平、既往伤病、偏好和不愿做的训练。

从本地库读取：最近训练频率、时长、项目分布、关键课与长课、强度/功率/配速（仅在数据可信时）、最近中断、主观 Check-in、睡眠等恢复线索、数据新鲜度和缺口。用户提供的信息与设备观测分开记录，不能把设备估计值伪装成用户确认事实。

### B. 安全和数据门槛

1. 出现胸痛、晕厥、异常呼吸困难等警讯时，停止自动开具训练课，提示寻求及时医疗评估；普通疼痛、疾病或功能受限时，不安排高强度并提示必要的专业评估。[美国心脏协会运动安全提示](https://www.heart.org/en/health-topics/cardiac-rehab/getting-physically-active/develop-a-physical-activity-plan-for-you)提供警讯依据。
2. 没有当天主观状态，不把用户判为“已恢复”；可以生成**保守草案**，但高强度课应等待确认。
3. 训练史不足、设备缺失或同步过期时，降级为保守起步方案，标明假设和低置信度；不填造 HR 区间、乳酸阈值、功率或目标配速。
4. 上述门槛属于产品安全策略，需要与合格专业人员评审，不能用现有 ACWR 数值阈值直接代替医学判断。

### C. 构建基线与目标路径

- 基线分别统计各项目近期训练暴露与变化；游泳、骑行、跑步的分钟数和设备“训练负荷”不能未经校准直接相加比较。
- 区分健康维持、能力提升、赛事表现和复训/恢复等目标；多目标冲突时先让用户排序。
- 对赛事目标，建立“当前水平 → 赛事需求”的阶段路径；对非赛事目标，以可持续习惯和阶段性能力指标为主。
- 初版计划可先覆盖未来数周的方向，但只把未来 7 天作为可确认执行的细节；长周期视图是可修订的预测，不是固定承诺。具体周期长度和项目规则需后续验证。

### D. 排课与渐进

先满足硬约束：可用时间、不可训练日、赛事日、疼痛/疾病限制、每周时长上限、必要恢复间隔；无解时报告冲突，不强行生成。

再优化软目标：项目专项性、连续性、关键训练课分布、容易执行的偏好、适当力量训练。训练类型、频率和强度以既往暴露与目标决定；不把“每周必增 10%”“必做 80/20”“每周必有间歇”写成通用硬规则。跑步/骑行/游泳需各自的课表库与进阶约束。

### E. 每日决策与每周复盘

- 每日根据新数据与简短 Check-in 给出“照常 / 降低 / 替代 / 暂停并评估”的建议；不因单次 HRV、Body Battery 或 ACWR 波动自动提高负荷。
- 每次训练后收集实际完成、RPE、症状和原因；比较**计划与实际**，而不只比较设备记录。
- 每周复盘目标进度、执行率、身体反应和数据缺口，提出新版计划。系统不得静默改写已确认计划；变更需展示差异和原因并由用户确认。

## 4. 产品交互与输出契约

对话流程：`确认目标 → 补最少必要信息 → 检查安全与数据 → 生成草案 → 解释关键取舍 → 用户修改/确认 → 保存版本 → 训练后反馈 → 下一版`。

每份草案至少包含：目标及日期、计划覆盖期、前提假设、各周/各项目总量、逐课日期/项目/类型/时长/强度表达、安排原因、替代课、暂停条件、数据缺口、置信度、证据 ID、与上一版差异。优先使用可理解的 RPE/谈话测试描述；只有个人阈值可靠时才给心率、配速或功率区间。模型负责对话解释和提问，确定性引擎负责约束、安全门槛、版本和保存。

## 5. 与现有实现的差距

当前 `TrainingPlanner.generate` 只按目标、7 天可用分钟数和单日安全等级顺序填课；`plan-create` 会直接保存。它未建立多周目标路径、项目专项课库、训练史驱动的渐进、草案确认、执行率驱动的滚动调整。现有安全规则把 ACWR 比率 1.5/1.8 当作固定风险边界；在上述证据下，不应把它直接升级为自动排课判据。

建议能力拆分为：`PlanContextBuilder`（带来源与新鲜度）→ `SafetyGate` → `SportStrategy` → `ConstraintSolver` → `PlanDraft`（只读预览）→ `PlanApproval`（确认后保存版本）→ `PlanReview`（实际完成与调整建议）。这复用现有本地数据、报告、计划版本和宿主适配，不在 Prompt 里复制核心规则。

## 6. 验证标准

- 单元/性质测试：硬约束绝不违反；缺数据不伪造强度；风险门槛始终覆盖优化目标；相同输入和规则版本产生可复现草案。
- 历史回放：只使用当时已知的数据生成计划，防止未来信息泄漏；检查可执行性、计划与实际偏差和异常提示。
- 小规模真实试用：记录接受/修改/完成率、主观负担、告警误报漏报、用户理解度；不以短期体重或“避免伤病”作为未经验证的成功宣称。
- 专业评审：运动训练和运动医学/营养相关人士分别审查项目课库、安全门槛及高风险转介话术。

## 7. 需要与用户确定的产品决策

1. 第一优先场景：跑步赛事、铁三/多项目、一般体能与健康、体重/体成分，哪个先做深？
2. 计划跨度：先做滚动 7 天，还是同时给 8–16 周赛事路径？长周期方案应允许每周修订。
3. 自动化边界：新数据到来后只**提出调整建议**，还是可自动修改未开始的课？本草案建议先采用“建议＋用户确认”。
4. 用户愿意每周/每日补充多少主观信息？它直接影响安全判断和计划个体化程度。

以上数字（如历史观察周数、计划周期）都是待验证的产品假设；除明确引用的人群指南外，不应当成适用于所有人的训练处方。
