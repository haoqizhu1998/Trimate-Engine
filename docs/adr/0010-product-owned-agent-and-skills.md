# ADR 0010：产品自有的Trimate Agent 与 Skill

- 状态：已接受
- 日期：2026-10-27

> **实现状态（2026-10-27）**：已有产品自有的版本化 Agent 入口、17 个产品 Skill（均有工具入口）、Codex 项目常驻入口与通用 LLM 包构建器，以及 Skill 身份、版本和 MCP 工具契约检查。当前 Codex 对话能调用本地 MCP；跑姿视觉环境和模型仍需本机安装，跨模型真实对话行为评测和 WorkBuddy/Coze 安装适配尚未交付。常驻入口的修订见 [ADR 0012](0012-always-on-training-partner-entry.md)。

## 背景

用户希望Trimate在不同模型软件中持续提供一致的训练服务。仅共享工具仍不足以保证各模型如何澄清目标、处理数据缺口、选择分析、解释证据、请求确认和跟进计划。把这些行为分别写在宿主 Prompt 中会造成方法漂移，也使产品价值依赖单一平台。

## 决策

### 1. Agent 和 Skill 是产品核心资产

产品维护一个Trimate Agent 定义，负责识别意图、管理对话旅程、选择 Skill、调用产品工具、解释结果和跟进反馈。Skill 是可独立版本化的训练场景方法：例如新手引导、日常训练复盘、目标共创与计划、恢复与身体反馈、赛事策略。它规定所需信息、追问顺序、能力调用、证据与缺口呈现、输出验收和何时移交专业人员。

训练方法、编排质量和个体化反馈是产品竞争力；不能把它们简化为一份通用系统提示词。产品将用合成案例和跨宿主行为评测来检验这些资产。每项定义至少声明稳定 ID、版本、适用场景、所需工具能力、输入与缺口、输出契约及评测案例。

### 2. 方法与状态各有权威来源

Agent/Skill 拥有对话和服务方法，但用户数据、目标/计划版本、同步状态、授权、分析证据与确定性安全规则由产品内核及用户私有库管理。Skill 可以规定“先检查恢复风险，再讨论训练量”，不能自行宣称用户已恢复、计划已生效，或绕过预览/确认工具直接写入。宿主对话记忆只作临时上下文，不替代产品状态。

个人数据持续增长且归用户所有；产品仓发布通用 Schema、算法、Agent/Skill 定义与合成案例，不发布任何人的真实数据或密钥。

### 3. 一份产品定义，多个宿主交付

产品维护宿主无关的 Agent/Skill 源定义。Codex/GPT、WorkBuddy、Coze 等适配器将其映射为该宿主支持的 Agent 指令、Skill、Workflow、工具描述或 UI 流程，并连接同一版本化工具契约。宿主包只处理安装、身份连接、工具映射和呈现差异，不复制训练算法或私有数据。

模型与宿主是两个维度。某个 LLM 能理解指令，不表示其宿主支持原生 Skill、MCP、后台任务或写入确认；只有完成工具连接、权限配置及该宿主的行为验收，才能声称产品能力在该组合中可用。纯文本对话可提供一般解释，不能冒充读取了用户私有数据或完成了写入。

### 4. 版本和验收

- 每个宿主包声明所映射的 Agent/Skill 版本和最低工具契约版本；能力缺失时明确降级或拒绝该流程。
- 对相同合成场景，检查必需工具调用、事实与证据、数据缺口、安全分支、确认步骤和输出要求；允许自然语言措辞不同。
- 训练方法更新需记录版本与变更影响，避免用户跨宿主得到互相矛盾的训练建议。
- 不以 Prompt 测试代替应用用例、安全规则、授权和连接器测试。

## 对现有决策的修订

[ADR 0007](0007-host-first-conversational-delivery.md) 中“Skill 是可选的宿主工作流说明”和“产品边界不是 Agent 或 Skill”的表述由本决策修订：产品自有的 Agent/Skill 是核心资产；**宿主原生 Skill 安装形式**仍可选。工具契约依然是执行和数据访问边界。ADR 0007 的本地优先、身份授权、确认和跨宿主工具复用原则继续有效。
