# ADR 0012：项目常驻Trimate与按需场景 Skill

- 状态：已接受
- 日期：2026-10-27

## 背景

把整个Trimate导出为宿主原生 Skill，会受宿主的 Skill 触发机制影响。用户询问产品使用、数据连接或同时提出多个意图时，Skill 可能没有被加载，Trimate就无法稳定参与整段产品对话。

## 决策

Trimate Agent 是**产品对话的常驻入口**。每轮先识别用户意图，再决定读取哪些产品状态、加载哪些场景 Skill、调用哪些用例。Skill 只是训练方法模块，既不能取代 Agent，也不能直接成为用户数据或业务状态的权威来源。一个请求可以组合多个 Skill；疼痛、疾病等安全信号优先。

Codex 项目使用项目级 `AGENTS.md` 加载产品 `experience/agent.md`，场景方法保留在 `experience/skills/`。构建器导出可放入目标项目的 `codex/AGENTS.md` 与同版 `experience/`，不再把整个Trimate导出成独立的 Codex Skill。其他模型宿主须把 `generic/agent.md` 装入每个产品对话的常驻指令，再按需提供场景方法和同版工具契约；仅复制文本文件不等于完成宿主安装或行为验收。

意图识别可以参考用户明确目标、已确认偏好和经过授权保存的反馈。聊天历史只能作为临时语境；持久的个人事实、目标、计划和行为反馈存在用户私有库，读取和写入须经过产品用例。LLM 负责理解、解释与工具编排；产品内核负责可验证计算、授权、持久化和安全规则。MCP 是宿主连接产品工具的一种协议，外部 API 是数据来源或业务能力，不是 Agent 本身。

## 验收

构建器与测试验证 Codex 包含常驻入口、Agent 定义及所有场景 Skill，且不再生成顶层Trimate Skill。跨宿主真实会话仍须分别测试意图路由、工具调用、数据缺口、安全覆盖和用户确认。WorkBuddy 已有可本地上传的 Skill ZIP 作为文件分发适配，但其上传入口不能自动注册常驻专家；需要客户端创建专家并验收。Coze 安装适配尚未交付。
