# ADR-0001：分离产品、研发过程与个人数据

- 状态：已接受，分阶段实施中
- 日期：2026-10-26

## 背景

当前目录同时承担 Garmin 数据迁移、密钥保存和未来产品开发。产品未来可能开源或商业发行，因此不能让个人数据、内部研发资料或商业策略成为产品运行依赖，也不能在发布时依赖人工清理敏感内容。

## 决策

采用三个相互独立的边界：

### 1. 产品仓：`athlete-growth`

可以开源或构建商业发行版，包含：

- 产品源码、数据库迁移、测试和公共技术文档；
- 连接器接口与实现；
- 确定性分析算法和 AI Provider 接口；
- 合成/匿名化示例数据；
- 技术 ADR、贡献指南和发布配置。

不得包含：真实个人数据、密钥、Token、内部详细路线图、用户访谈、定价或销售材料。面向用户和贡献者的公开能力路线图可以保留在产品仓。

### 2. 私有产品运营仓：`athlete-growth-product-ops`

只用于产品研发与商业过程，包含：

- 未公开的产品愿景、调研、需求池、详细路线图和优先级；
- Sprint、会议纪要、复盘和发布协调；
- 商业模式、定价、渠道、销售与合作资料；
- 内部风险、决策背景和未公开实验。

它可以引用产品仓的 Issue、版本和文档，但产品仓不能依赖它构建或运行。具体 Sprint、实验、商业优先级和未发布决策仍属于私有仓。

### 3. 本地个人数据保险库：`ATHLETE_GROWTH_HOME`

位于源码仓之外，默认建议 `~/.athlete-growth/`，并按 `profiles/<athlete-id>/` 隔离，包含：

- Garmin 导出包、FIT/TCX/JSON；
- 标准化数据库、派生指标和个人报告；
- API Key、OAuth Token、模型密钥；
- 缓存、日志、备份和用户配置。

保险库不进入 Git；未来如需云同步，必须使用独立加密和授权机制。

## 依赖规则

```text
私有产品运营仓 ──引用──> 产品仓
个人数据保险库 ──挂载──> 产品运行实例
产品仓 ──不得依赖──> 私有产品运营仓或某个人的数据
```

## 对当前目录的迁移建议

当前不立即移动文件，避免破坏已完成的 Garmin 迁移证据。后续按以下顺序执行：

1. 先初始化新的产品包、测试和配置；
2. 为现有脚本补回归测试；
3. 将通用 FIT/TCX 逻辑迁入产品适配器，并保留兼容 CLI；
4. 将 `data/` 和 `.secrets/` 迁入数据保险库；
5. 校验 783 条活动和 127 条转换结果后，再从产品工作树移除旧运行数据；
6. 在产品仓外新建私有产品运营仓。

## 结果

优点：

- 可从一开始控制开源泄密风险；
- 商业策略不会污染公共源码和发布包；
- 真实个人数据可以独立备份、迁移和删除；
- 同一产品代码可以服务单用户、本地部署或未来托管版本。

代价：

- 需要维护三个明确位置；
- 开发环境必须显式配置数据目录；
- 测试必须准备合成或匿名化 Fixture，不能直接依赖个人数据。

- Web/App 是否进入同一产品仓。
