# 产品能力地图

本地图描述产品应该具备的业务能力和优先级，不等同于内部 Sprint 或商业路线。能力是否完成必须由用户闭环和验收标准判断，而不是以页面或接口数量判断。

## 实现状态

阶段 0–5 的本地模块、CLI 和自动化测试已实现；阶段 5.5 的模型宿主安装与对话式引导已完成设计但尚未开发，阶段 6 未开发。当前可用入口覆盖 `init/status`、采集同步、Check-in、目标、日报/周报、计划、质量、数据权利、恢复、营养、赛事和离线 AI。外部 Garmin 与云模型是否可用仍取决于用户授权及服务状态，实时天气/赛事数据采用可替换输入，不作为核心离线闭环的前提。

## 核心闭环

```text
目标 → 计划 → 执行 → 客观数据 + 主观反馈
  ↑                              ↓
  └──── 个人响应学习 ← 分析与安全判断
```

## 能力分层

| 能力域 | MVP | 下一阶段 | 后续扩展 |
|---|---|---|---|
| 安装与宿主交互 | 宿主无关引导状态、统一工具契约、进度和失败恢复 | GPT/Codex、WorkBuddy、Coze 宿主包与跨宿主续接 | 更多模型宿主与宿主市场分发 |
| 个人档案 | 基础资料、单位、时区、健康限制、时间硬约束 | 装备、场地和训练偏好 | 家庭/教练授权档案 |
| 数据授权 | 数据源授权、AI 外发控制、撤回 | 保留策略、授权审计 | 组织级策略 |
| 数据采集 | Garmin CN、文件导入 | 国际区和其他设备 | 社区连接器 SDK |
| 主观 Check-in | 疲劳、酸痛、疼痛、情绪、意愿、疾病、RPE | 工作压力、旅行、酒精、环境 | 自定义问卷 |
| 数据质量 | 去重、缺失、来源、异常值 | 设备变化、来源冲突、质量评分 | 自动修复建议 |
| 目标管理 | 运动、身体、赛事目标 | 目标冲突、情景模拟 | 教练共同目标 |
| 训练分析 | 负荷、强度、连续性、单次复盘 | 个人基线、心率漂移、响应分析 | 专项高级模型 |
| 恢复与安全 | 每日恢复、安全硬规则、风险升级 | 复训流程、长期异常趋势 | 专业人员协作接口 |
| 计划执行 | 计划状态、完成度、跳过原因 | 动态调整、版本回滚 | Garmin 写入与多日历 |
| 成长反馈 | 日报、周报、个人最佳、里程碑 | 周期复盘、个人响应学习 | 长期能力画像 |
| 营养 | 基础训练/比赛补给建议 | 饮食计划和偏好约束 | 高级能量平衡 |
| 赛事 | 目标赛事和基础策略 | 路线、天气、海拔、补给 | 赛事数据库与协作 |
| AI | 单一云模型与本地/兼容模型、证据引用 | 路由、评测、纠正学习 | 托管模型与高级代理 |
| 数据主权 | 导出、备份、恢复、删除 | 跨设备迁移 | 自托管/云端同步 |
| 协作 | 无 | 只读报告分享 | 教练、多运动员、团队 |
| 技术技能 | 训练笔记与动作标签 | 技术练习库 | 视频动作分析 |

## MVP 必须回答的用户问题

1. 我的数据是否完整、来自哪里、现在是否同步成功？
2. 我今天的客观恢复数据和主观感受分别怎样？
3. 今天原计划做什么，安全规则是否要求调整？
4. 最近一周训练是否符合目标，出现了哪些趋势或风险？
5. 一条建议依据了哪些数据，哪里存在不确定性？
6. 我是否采纳了建议，实际结果如何？
7. 我能否随时导出、备份、恢复或删除自己的数据？
8. 我如何在当前 AI 宿主安装，并在更换宿主后继续使用同一份数据？

## 产品级验收指标

- 同步完整性：无静默丢失，来源记录可追溯；
- 建议可解释性：关键建议均有证据和算法/模型版本；
- 安全性：硬约束和高风险信号不能被 AI 绕过；
- 闭环率：计划、执行、反馈和调整能够串联；
- 用户控制：授权可撤回，数据可完整导出和恢复；
- 模型独立性：更换或停用 AI 不影响核心指标和历史数据；
- 可迁移性：本地模式能够升级到自托管或商业云而不丢数据。
- 宿主独立性：更换 GPT/Codex、WorkBuddy、Coze 等入口不改变训练事实、安全结论和引导进度。

## 明确排除在早期版本之外

- 疾病诊断、治疗、药物或处方建议；
- 实时生命安全监测和紧急响应；
- 无确认的自动增量训练或数据删除；
- 社交排行榜、内容社区和复杂插件市场；
- 依赖个人真实数据才能运行的测试或 Demo。
