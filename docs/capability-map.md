# 产品能力地图

状态说明：✅ 已有代码和自动化测试；🟡 部分实现或仍需用户真实环境验收；⬜ 尚未实现。这里的“完成”不代表外部服务可用性、真实账户登录或后台安装已经在用户机器上验证。

耐力运动专项的 Skill/工具职责、已知短板和新增顺序见[专项盘点](endurance-skill-tool-review.md)。

GPT/Codex、WorkBuddy、Coze 是对话载体；佳明、高驰是产品通用设备来源。下表按能力状态区分，不按载体划分设备。

## 当前闭环

```text
目标 → 计划 → 执行 → 客观数据 + 主观反馈
  ↑                              ↓
  └──── 个人响应学习 ← 确定性分析与安全判断

可访问来源 → 本地轮询 → 私有保险库 → 真实变化 → 分析快照 → 通知策略
```

## 自动通知的精确边界

| 模式 | 有真实变化时 | 无变化时 |
|---|---|---|
| `actionable-digest` | 中/高风险立即；低/未知风险排到本地摘要小时 | 不分析、不通知 |
| `all` | 每个变化集立即创建一条通知 | 不分析、不通知 |
| `off` | 保存分析快照；不为新分析创建通知；保留既有 Inbox/历史与待投递项，但抑制发送 | 不分析、不通知；重新启用后仍待投递的到期项可恢复投递 |

通知的“摘要”目前是延时投递策略，不代表会把多个变化集合并成一封日报。外部投递是至少一次；macOS 已接受而回执尚未落库时崩溃，恢复后可能罕见重复一次。

## MVP 能回答的问题

1. 我的数据来自哪里，最近一次自动运行是否成功？
2. 当前策略、下次运行、失败或待恢复任务是什么？
3. 这批数据是否真的变化，分析依据对应哪份冻结投影和原始证据？
4. 我今天与最近一周的确定性状态、数据缺口和安全级别是什么？
5. 为什么现在提醒、延后到摘要，或完全不提醒？
6. 我能否查看/标记 Inbox，并导出、备份、恢复或删除数据？
7. Mac 休眠或断网后怎样补拉，当前回看窗口是否足够？

## 明确排除

- 疾病诊断、治疗、药物、处方建议；
- 实时生命安全监测、医疗报警或紧急响应；
- 未确认的 Garmin 写回或数据删除；
- 将模型宿主当作可靠队列或凭据保险库；
- 声称本地 Mac Worker 是全天候托管服务；
- 依赖个人真实数据才能运行的测试或 Demo。
