# 单次训练分析输出契约

单次训练分析先返回可核验的结构，再由 Trimate 结合已确认计划、近期状态和用户体感写成反馈。`analyze_session.analysis_sections` 固定区分六类证据：

| 部分 | 能说明什么 | 不能据此说明什么 |
|---|---|---|
| `session` | 活动日期、项目、名称和记录 ID | 训练目的或计划完成状态 |
| `external_output` | 记录的距离、时长、功率、爬升及由距离和时长换算的配速/均速；有设备均速时并列核对两种口径 | 未记录的间歇强度、精确生理负荷；均速不一致时不能直接说能力变化 |
| `internal_response` | 平均/最高心率及设备负荷等现有字段 | 没有个体基准和 RPE 时的强度区间、疲劳原因或恢复状态 |
| `within_session_pattern` | 可比分圈的前后半程中位数；若圈段完整，还并列展示心率/功率中位数变化 | 单凭前后变化判定疲劳、跑崩、配速错误或能力变化 |
| `history_reference` | 同来源项目、距离与时长相近的历史记录中位数和样本数 | 没有控制训练目的、路线、天气和强度的进步/退步结论 |
| `training_intent`、`evidence_quality` | 已记录课型、详情同步状态、来源、质量标记和缺口 | 从活动名称自动确认目标、从缓存样本声称已分析逐点数据 |

对话反馈按“一句话发现 → 训练定位与完成 → 过程和身体反应 → 历史参照 → 下一步 → 证据缺口”组织。只有存在实际证据的部分才展开；每项判断标明观测、计算、用户自述或待核对推测。缺少计划关联时，不判定完成；缺少主观状态时，不推断疲劳或恢复。`compare_plan_actual` 仅计算已指定计划课的日期、项目、时长和距离差异，缺少任一目标时相应差异为 `null`。

分圈方向只说明指标数值变化：跑步/游泳配速越高代表单位距离耗时越长，骑行均速越高代表速度越快。圈段心率升高与配速变慢可以并列观察，但坡度、气温、间歇步骤、停顿和设备误差尚未控制，不能输出确定原因。计划执行、RPE 和疼痛的保存仍须用户核对、预览及确认。
