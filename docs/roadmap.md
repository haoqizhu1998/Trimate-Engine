## 阶段 0：工程与数据边界

**状态：本地代码完成。**

已交付：

- Python 包、CLI、测试和静态检查配置；
- Profile/`athlete_id` 隔离与私有 Vault；
- 标准记录版本、原始证据引用、SQLite Repository；
- 导出、备份、恢复和确认删除；
- 合成 Fixture 与不依赖个人数据的测试；
- 产品代码、个人数据和私有研发/运营过程的边界。

阶段 0 不代表已经完成 GitHub 发布或正式发行；当前源码和 Agent/Skill 采用 Apache-2.0 许可证，公开发布前仍需核对私有数据边界和发行包。

## 阶段 1：中国区个人数据闭环

**状态：代码完成，真实环境验收待用户执行。**

已交付：

- Garmin 中国区本地网页会话、只读 Poll 和独立 Token 目录；
- 活动、每日汇总、步数、睡眠、HRV、心率、压力、身体电量和体重；
- CSV、JSON、TCX、FIT 导入；
- 增量游标、内容/来源去重、原始证据和数据质量命令；
- 主观 Check-in 与生活情境；
- 外部连接失败不覆盖已有数据。

仍未证明：某个真实账号当前可登录、Garmin 非官方接口未来持续可用，以及连续多日后台运行无外部故障。这些不能由合成契约测试代替。

## 阶段 2：档案、目标与确定性分析

**状态：本地代码与自动化测试完成。**

已交付：

- Profile、单位和时区；运动、身体与赛事目标及冲突；
- 训练负荷、强度、连续性、心率漂移和恢复观测；
- 确定性日报、周报、数据缺口、算法版本和证据；
- 疼痛、疾病、恢复异常与负荷风险的安全规则；
- AI 不可用时仍能生成核心结果。

产品仅提供训练和一般健康指导，不提供医学诊断或紧急监护。

## 阶段 3：训练计划、调整与反馈

**状态：基础计划与草案确认流程已有代码和自动化测试；完整个体化计划待开发。**

已交付：

- 按目标、开始日期、可训练时间、不可训练日、每周上限和近期训练时长生成保守 7 天计划；可选专项重点、关键课日和跨项目有氧，并标明未排到的项目；
- 预览 2–12 周重点项目轮换；只确认首周逐日草案，后续每周结合新证据和安全状态重新预览；
- 同周单节课的用户主动改动可预览与确认；新活动进入后提示可能的计划偏差，不自动判定执行结果或改写已批准计划；
- 从用户想法创建/修订目标草案；已确认目标可经预览和确认替换、删除；7 天计划预览与确认后保存，目标或新数据变化时复核并生成新版差异草案，拒绝过期草案；
- 训练状态、计划版本、调整、回滚和执行反馈模型；
- 成长里程碑与个人响应学习；
- 私有成长画像、每日训练选择的证据绑定预览/确认、反馈修订、候选适应的单独确认和撤回；适应只调整低风险日推荐，不修改安全规则或已确认计划；
- 用户声明专项测试结果的预览/确认与版本化；过期或估计值不作为计划区间参考；多周预测增加保守周量上限、恢复周、赛前一周与赛事周提示，未来周仍需重新预览；
- 用户确认计划课与活动的对应、完成状态及主观 RPE/疼痛；部分完成或跳过时下一周不提高预测上限，近期疼痛未复核时暂停重新排课；
- 同日或相邻日新活动形成唯一、跨日或有歧义的计划课候选，额外活动单列供用户核对；仅在用户确认后写入执行反馈；
- 相关性与因果边界；
- 远程训练写回的预览/显式确认端口。

尚未交付完整目标澄清与可行性评估、自动渐进的多周专项处方、独立真人确认通道、完整 Garmin Workout 远程写回适配器或日历 UI。成长系统当前只覆盖每日训练选择与一种保守适应，尚无完整偏好模型或自动批准的周期计划调整。旧 CLI `plan-create` 仍是直接保存路径。

## 当前用户还需要亲自完成的步骤

1. 在自己的终端初始化 Profile，或确认现有保险库可用。
2. 交互式完成 Garmin 中国区会话登录；仓库没有代用户登录。
3. 运行 `automation-configure`，确认轮询、回看和通知策略。
4. 运行 `automation-run-once --force`，检查 `automation-status` 和 Inbox。
5. 只有接受本地后台运行行为后，明确运行 `automation-install-macos`。
6. 在 macOS 设置中确认通知权限，并观察真实网络/睡眠/唤醒场景。
7. 断网可能超过回看窗口时，调大 `--lookback-days` 再补拉。

详细步骤见 [新手与模型宿主引导](onboarding.md) 和 [自动化运行手册](operations.md)。
