# 产品路线图

路线图按“可验证的用户闭环”推进，而不是按功能数量推进。时间仅用于排序和容量估算，可在执行前按投入调整。

| 阶段 | 代码状态 | 验证状态 |
|---|---|---|
| 0 | 已完成 | 安装、数据权利、回归、测试和静态检查已验证 |
| 1 | 已完成 | 合成契约和文件闭环已验证；中国区外部服务与连续 14 天实运行待用户环境验收 |

| 3 | 已完成 | 约束计划、状态、调整、回滚、写回确认和个人响应已验证 |
| 4 | 已完成 | 多 Provider 契约、隐私/成本路由、降级、安全覆盖和审计已验证 |
| 5 | 已完成 | 复训、营养、赛事来源与离线策略已验证；实时赛事/天气服务使用用户输入或文件适配器 |
| 5.5 | **规划完成，未开发** | 自动同步/分析/通知、模型宿主安装、对话式引导和跨宿主恢复待实现 |
| 6 | **未开发** | 独立 Web/App、托管、发布、许可证与商业化均不在本次范围 |

“代码完成”表示本地产品能力和自动化验收已交付，不等于外部服务的长期运行证明。特别是 Garmin 中国区的可用性、账户权限和连续 14 天同步必须在用户真实环境中观测，不能由合成测试代替。

## 阶段 0：工程与边界基线

**状态**：代码与本地验收完成。

**目标**：把当前脚本集合变成可安全演进的产品工程。

交付：

- 建立产品仓、私有产品运营仓和本地数据保险库边界；
- 创建 Python 包、配置系统、测试框架和数据库迁移；
- 建立 `athlete_id` 数据归属、Profile 隔离和本地数据保险库；
- 建立授权、导出、备份、恢复、更正和删除的基础接口；
- 为现有 Garmin 导出与 FIT→TCX 流程补充回归测试；
- 写入核心 ADR：数据分层、连接器接口、一般健康边界、AI 安全和隐私策略；
- 准备合成数据 Fixture，测试不依赖个人真实数据；
- 现有脚本保持可运行，迁移采用兼容入口。

退出标准：

- 新环境可以从 README 完成安装；
- 密钥和真实数据不在 Git 跟踪范围；
- 任一 Profile 可以独立导出、备份、恢复和删除；
- 撤回授权后对应连接器或 AI Provider 不能继续访问数据；
- 783 条活动提取结果和 127 条转换结果可重复验证；
- 单元测试、静态检查和最小启动检查通过。

## 阶段 1：中国区个人数据闭环（MVP 基础）

**状态**：代码完成；中国区服务连通性和连续 14 天实运行验收待执行。

**目标**：每天能稳定获取并查看自己的最新训练与恢复数据。

交付：

- Garmin 中国区本地会话只读连接器，不依赖 Personal API Key，Token 与国际区完全隔离；
- FIT/TCX/CSV 文件导入作为离线兜底；
- 标准化活动、睡眠、HRV、心率、压力、身体电量、步数和体重；
- 每日主观 Check-in：疲劳、酸痛、疼痛、情绪、训练意愿、疾病和 RPE；
- 可选生活情境：工作压力、旅行、时差、酒精和环境事件；
- 增量同步、幂等去重、失败重试、同步游标和数据质量报告；
- Profile 级本地数据目录、可验证备份与恢复；
- CLI：`sync`、`status`、`check-in`、`today`、`activity`、`data-quality`、`export`、`backup`。

退出标准：

- 连续 14 天增量同步无重复、无静默丢失；
- 任一标准化记录可以定位到原始来源；
- 缺失 Check-in 不会被解释为“状态良好”；
- 数据源冲突、设备变化和异常值会明确提示；
- 连接失败不会损坏已有数据；
- 中国区连接失效时仍可通过导出文件恢复数据。

## 阶段 2：个人资料、目标与分析闭环（MVP 完成）

**状态**：代码与自动化验收完成。

**目标**：回答“我现在处于什么状态、是否在向目标靠近”。

交付：

- 个人资料和运动/身体/赛事目标管理；
- 可训练时间、不可训练日、场地、装备和健康硬约束；
- 目标优先级、目标冲突识别和取舍建议；
- 个人基线：HRV、睡眠、静息心率、体重、训练量；
- 训练负荷、强度分布、连续性、心率漂移和计划完成度；
- 安全规则：疼痛、疾病、异常恢复和负荷突增的风险升级；
- 每日恢复摘要、活动复盘和每周训练报告；
- 每个结论包含证据、算法版本、数据缺口和置信度。

退出标准：

- 日报和周报不依赖 AI 也能生成结构化结果；
- 相同输入和算法版本得到相同指标；
- 缺失数据不会被解释为零；
- 高风险信号先经过确定性安全规则，AI 不能绕过；
- 产品不输出疾病诊断或治疗结论；
- 用户能够修正资料、目标和异常记录。

## 阶段 3：训练计划与动态调整

**状态**：代码与自动化验收完成。

**目标**：从分析走向可执行、可反馈的成长计划。

交付：

- 基于目标、周期、时间预算、运动水平和限制生成计划；
- 计划状态：草拟、批准、安排、完成、部分完成、跳过、替代、取消；
- Planned vs Actual 对比、未完成原因和用户主观效果；
- 根据恢复、未完成训练和负荷风险给出调整建议；
- 训练日历、计划版本和变更原因；
- 成长时间线、个人最佳、里程碑和周期复盘；
- 目标冲突的场景模拟，以及不同训练刺激后的个人响应学习；
- Garmin Workout 写入作为可选能力，默认关闭且要求确认。

退出标准：

- 计划中的每次训练可以解释其目标和负荷；
- 自动调整不会突破用户的硬约束；
- 用户可以拒绝或纠正建议，反馈进入下一周期而不改写历史；
- 个人响应分析区分相关性与因果结论；
- 所有写回动作可预览、确认和审计；
- 计划版本可回滚。

## 阶段 4：多模型 AI 教练

**状态**：代码与适配器契约验收完成；外部模型实际调用需要用户另行授权和配置。

**目标**：在不绑定单一模型的前提下提供自然交互和个性化解释。

交付：

- OpenAI、Anthropic、Gemini、OpenAI-compatible 与本地模型适配器；
- 模型路由、成本上限、隐私模式和失败降级；
- 结构化工具调用、Prompt 版本和 ModelRun 审计；
- “为什么这样建议”的证据引用、证据覆盖率和不确定性；
- 云端外发预览、最小数据授权和本地模型隐私模式；
- 用户纠正记录及跨模型固定评测集；
- 离线规则引擎作为核心功能兜底。

退出标准：

- 更换模型不改变领域数据和确定性指标；
- 模型不可用时同步、分析和报告仍可运行；
- 高风险建议通过规则校验；
- 用户撤回模型授权后不再发生新的外发；
- 评测集覆盖事实错误、过度训练、用户纠正和医疗越界场景。

## 阶段 5：恢复、营养与赛事策略

**状态**：本地/文件闭环与自动化验收完成；实时天气和赛事服务不是硬依赖。

**目标**：形成训练之外的完整备赛闭环。

交付：

- 面向复训的伤病状态、恢复记录与长期恢复趋势；
- 伤病后的复训状态与渐进回归流程，但不提供医疗诊断；
- 日常饮食与训练/比赛补给计划；
- 赛事目录、路线、海拔、天气和历史成绩连接器；
- 旅行、时差、海拔、天气和工作压力对计划的情境调整；
- 配速/功率、补给、装备、交通和风险策略；
- 赛后复盘并回写下一训练周期。

退出标准：

- 赛事数据明确来源、更新时间和授权边界；
- 饮食计划能反映训练日和比赛日差异；
- 非医疗声明和风险升级路径清晰；
- 策略可导出为离线使用的文档。

## 阶段 5.5：自动闭环、模型宿主交付与新手引导

**状态**：架构与交互规划完成，代码未开发；这是当前最高开发优先级。

**目标**：让没有命令行经验的新用户直接在 ChatGPT/Codex、WorkBuddy 或 Coze 中完成“安装 → 连接 → 同步 → 首次报告 → 目标 → Check-in → 首周计划”，此后由后台运行器自动同步新数据、重新分析并告知用户。

交付：

- 应用层可持久化、可恢复的新手引导状态机；
- Push/Poll/Manual 统一同步协调器、可恢复后台运行器和来源级频率策略；
- `DataChangeSet → AnalysisSnapshot → NotificationOutbox` 持久化事件链；
- 数据质量、确定性分析和安全规则自动执行，AI 失败不阻断核心结果；
- 通知 Inbox、安静时段、合并去重、即时/摘要/全部/关闭策略；
- 宿主通知、本机系统通知和邮件的可替换端口；
- 版本化 Tool Catalog 和宿主无关的结构化结果契约；
- MCP Server 与 HTTP/OpenAPI Bridge，共用相同应用用例；
- ChatGPT/Codex、WorkBuddy、Coze 三套宿主包和契约测试；
- 宿主能力协商、一次性本地配对、远程 OAuth/OIDC 和身份映射；
- 同步进度、失败恢复、数据成熟度与空状态说明；
- 导出、删除、外发和训练写回的预览、短时效确认与审计；
- CLI 保留为维护、恢复、开发和无宿主降级入口。

退出标准：

- 新用户首次价值时间中位数小于 10 分钟；
- 用户关闭对话或更换宿主后能从原状态继续；
- 三个宿主对同一引擎输入得到一致的事实、安全结论和证据引用；
- Garmin Token、模型密钥、数据库路径和原始健康数据不会进入宿主 Prompt、变量或日志；
- 安装、授权和同步失败均给出可执行的恢复动作，安全重试不会产生重复数据；
- 有效新数据无需用户发命令即可被发现、写入个人数据库并生成分析快照；
- 后台运行器健康时，在一个已展示的轮询周期内发现数据，落库后 2 分钟内完成核心分析；
- 支持主动通知的健康渠道在分析完成后 2 分钟内收到可行动结果或排入明确的摘要时间；
- 重复来源信号、进程重启或部分失败不会重复分析、重复提醒或丢失任务；
- 本地运行器离线时明确显示数据新鲜度，恢复后自动补拉；
- 支持主动通知的渠道按策略投递，不支持的宿主在下次会话显示未读结果；
- 敏感动作未经引擎侧确认令牌不得执行。

详细交互见 [模型宿主优先的新手引导](host-first-onboarding.md)，宿主架构见 [ADR 0007](adr/0007-host-first-conversational-delivery.md)，自动闭环见 [ADR 0008](adr/0008-durable-automatic-data-loop.md)。

## 阶段 6：开源与商业化产品化

**状态**：未开发。

**目标**：让产品可以安全开源，也可以形成商业发行版。

交付：

- 稳定公共 API、宿主包与独立安装包、跨版本升级和恢复验证；
- Web/App 界面与可访问性；
- 脱敏 Demo 数据和贡献指南；
- 版本兼容、遥测选择、崩溃报告和安全披露流程；
- 商业版可选能力：托管同步、跨设备、多运动员/教练协作、托管 AI、高级多渠道通知、赛事服务和专项视频技术分析；
- 在发布前单独确定许可证及开源核心边界。

退出标准：

- 产品仓可独立构建、测试和发布；
- 发布包不包含个人数据、内部路线图或商业资料；
- 本地数据可以无损导出并迁移到新版本；
- 开源版不存在依赖私有仓才能工作的隐藏路径。

## MVP 优先级

### 必须有

- 自动增量同步、离线补拉和运行状态可见；
- 数据变化自动触发确定性分析与安全规则；
- 可配置通知策略、未读收件箱和失败恢复；
- Garmin 中国区只读同步与文件导入兜底；
- 活动、睡眠、HRV、心率、压力、身体电量和体重标准化；
- 每日主观 Check-in 与现实训练约束；
- 个人资料与三类目标；
- 安全规则、一般健康边界和风险升级；
- 每日恢复摘要、单次活动复盘、每周训练报告；
- 数据来源、证据与质量提示；
- 本地存储、Profile 隔离、授权、导出、备份、恢复和删除。

### 应该有

- 训练计划与动态调整；
- 一个云端模型和一个本地/兼容模型适配器；
- 训练日历和计划完成度；
- 计划执行反馈、成长时间线和基础个人响应学习；
- FIT 逐秒数据分析。

### 后续再做

- 营养精细化记录；
- 赛事数据库与天气集成；
- 写回手表；
- 多用户、教练协作、支付和托管服务；
- 专项动作视频分析；
- 动态插件市场。

## 主要风险与对策

| 风险 | 对策 |
|---|---|
| Garmin 非官方接口变化 | 固定兼容版本范围、连接器隔离、契约测试、只读限制、文件导入兜底 |
| 后台运行器离线或任务丢失 | 持久化任务、心跳与数据新鲜度提示，设备恢复后按游标补拉 |
| 重复分析或通知疲劳 | 数据水位幂等、批次合并、去重冷却、安静时段和可选摘要 |
| 模型宿主协议或权限变化 | Tool Catalog 保持宿主无关、MCP/OpenAPI 双适配、宿主包单独版本化并在发布前复验 |
| AI 幻觉或过度训练建议 | 确定性指标、结构化输出、证据引用、硬规则校验 |
| 医疗边界 | 明确非医疗定位、风险信号升级、避免诊断表述 |
| 个人数据泄露 | 本地优先、最小外发、密钥隔离、日志脱敏 |
| 用户过度依赖自动建议 | 展示不确定性、保留用户确认、支持纠正与专业帮助升级 |
| 设备或来源数据冲突 | 来源优先级、质量评分、冲突提示、保留原始证据 |
| 赛事数据授权问题 | 记录来源与许可，优先官方 API 或用户导入 |
| 过早复杂化 | 模块化单体、少量稳定工具、宿主包薄适配、按退出标准逐阶段扩展 |
| 开源与商业边界混乱 | 产品仓独立可运行，商业能力通过清晰接口叠加 |
