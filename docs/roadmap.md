## 阶段 0：工程与数据边界

**状态：本地代码完成。**

已交付：

- Python 包、CLI、测试和静态检查配置；
- Profile/`athlete_id` 隔离与私有 Vault；
- 标准记录版本、原始证据引用、SQLite Repository；
- 导出、备份、恢复和确认删除；
- 合成 Fixture 与不依赖个人数据的测试；
- 产品代码、个人数据和私有研发/运营过程的边界。

阶段 0 不代表项目已经正式开源；当前 `pyproject.toml` 许可证仍为 `Proprietary`。

## 阶段 1：中国区个人数据闭环

**状态：代码完成，真实环境验收待用户执行。**

已交付：

- Garmin 中国区本地网页会话、只读 Poll 和独立 Token 目录；
- 活动、每日汇总、步数、睡眠、HRV、心率、压力、身体电量和体重；
- CSV、JSON、TCX、FIT 导入；
- 增量游标、内容/来源去重、原始证据和数据质量命令；
- 主观 Check-in 与生活情境；
- 外部连接失败不覆盖已有数据。

仍未证明：某个真实账号当前可登录、Garmin 非官方接口未来持续可用，以及连续多日后台运行无外部故障。这些不能由合成契约测试代替。

## 阶段 2：档案、目标与确定性分析

**状态：本地代码与自动化测试完成。**

已交付：

- Profile、单位和时区；运动、身体与赛事目标及冲突；
- 训练负荷、强度、连续性、心率漂移和恢复观测；
- 确定性日报、周报、数据缺口、算法版本和证据；
- 疼痛、疾病、恢复异常与负荷风险的安全规则；
- AI 不可用时仍能生成核心结果。

产品仅提供训练和一般健康指导，不提供医学诊断或紧急监护。

## 阶段 5.5：自动闭环与模型宿主交付

**状态：本地自动核心和 macOS 适配器已完成；宿主传输与跨平台部分待开发。**

### 已实现

- `SyncSubscription`、`SyncRun`、`DataChangeSet`、`AnalysisSnapshot`、`UserNotification` 持久化链；
- Garmin CN 到期轮询、手动强制运行和回看补拉；
- 真实变化触发、纯重复跳过、冻结分析投影；
- 原子领取、租约、续租、fencing 和过期任务恢复；
- Raw Evidence 哈希/路径验证，缺失或篡改时拒绝恢复分析；
- 不依赖 AI 的自动日报、周报和安全规则；
- `actionable-digest`、`all`、`off` 三种精确通知模式；
- 本地 Inbox、已读、投递租约、指数退避和至少一次语义；
- macOS Notification Center；
- macOS `launchd` 安装/卸载，以及状态和一次运行 CLI；
- JSON-safe 的宿主无关自动化 facade。

### 仍待实现

- GPT/Codex 的 MCP/Plugin/OpenAPI 产品传输与安装包；
- WorkBuddy MCP/Skill/Workflow 和 Coze Plugin/OpenAPI/Workflow；
- 完整版本化 Tool Catalog、对话式引导状态机和跨宿主续接；
- 官方 Garmin 商业 OAuth 和 Push/Ping-Pull；
- 邮件、移动推送和宿主主动消息；
- Windows Task Scheduler、Linux systemd 与容器化常驻 Worker；
- 远程身份映射、OAuth/OIDC 和托管多用户运行。

当前 GPT/Codex 可以作为帮助用户理解和执行本地步骤的对话宿主，但产品尚没有可安装的 GPT 传输适配器。未来所有宿主都必须复用同一 facade 和确定性核心。

## 当前用户还需要亲自完成的步骤

1. 在自己的终端初始化 Profile，或确认现有保险库可用。
2. 交互式完成 Garmin 中国区会话登录；仓库没有代用户登录。
3. 运行 `automation-configure`，确认轮询、回看和通知策略。
4. 运行 `automation-run-once --force`，检查 `automation-status` 和 Inbox。
5. 只有接受本地后台运行行为后，明确运行 `automation-install-macos`。
6. 在 macOS 设置中确认通知权限，并观察真实网络/睡眠/唤醒场景。
7. 断网可能超过回看窗口时，调大 `--lookback-days` 再补拉。

详细步骤见 [新手与模型宿主引导](onboarding.md) 和 [自动化运行手册](operations.md)。
